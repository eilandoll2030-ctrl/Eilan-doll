# تعاون الوكلاء على مستودع إيلان دول

> ملف داخلي للفريق التقني. **مستبعد من النشر** (`team/` في `.vercelignore`).
> آخر تحديث: ٧ نوفمبر ٢٠٢٦ — بتوقيت الرياض.

---

## ١. ليش هذا الملف

المالكة تعطي أوامر لأكثر من وكيل (Arena، Cloud، وأي وكيل جديد). الموقع كله في **ملف واحد** `index.html` (~٢.٣ ميجا)، فأي شغل متوازي على نفس المنطقة يسبب تعارض أو شغل مكرر. هذا الملف يحدد قواعد التعاون حتى **ما يقدر وكيل يكتب فوق شغل وكيل ثاني**.

---

## ٢. القاعدة الذهبية

> **مهمة واحدة = وكيل واحد = فرع واحد = طلب دمج واحد.**

لا يوجد استثناء لهذه القاعدة. لو المالكة أعطت نفس الطلب لاثنين، الوكيل الثاني يوقف ويسأل قبل ما يبدأ.

---

## ٣. خريطة المناطق (من يشتغل وين)

| المنطقة | الملفات / الصفحات | الوكيل المسؤول |
|---|---|---|
| الأكاديمية والجهات والدورات | `index.html` ← `P.learn` · `P.provider` · `EXT_*` · `PROVIDERS` · بيانات `extCourses` | Arena |
| القوالب والاستوديو والمواقع | `index.html` ← `P.templates` · `P.studio` · `TP_*` · `P.websites` | Cloud |
| المتجر والمنتجات والعروض | `index.html` ← `P.store` · `P.product` · `P.offers` | Cloud |
| بقية الأقسام | `games/` · `visual/` · `coloring/` · `edu/` · `api/` (منفصلة عن `index.html`) | أي وكيل — بشرط إشعار الثاني في اللوحة |
| الهوية والألوان والشعار | `.css` داخل `index.html` + `assets/` | لا أحد بدون أمر صريح من المالكة |

**قاعدة التداخل:** لو المهمة تلمس منطقة وكيل ثاني (مثلاً إصلاح في `index.html` مشترك)، يكتب صاحبها في اللوحة قبل البدء، ويبدأ **بعد** ما يخلص الثاني ويدمج.

---

## ٤. خط سير الشغل (٥ خطوات)

```
١. المالكة تعطي الأمر لوكيل واحد
٢. الوكيل يكتب في اللوحة: current = «شغال على …» + يسحب آخر main
٣. الوكيل يشتغل على فرعه → فحص → رفع الفرع → طلب دمج (PR)
٤. المالكة ترد «ادمجه» → الوكيل يدمج → ينشر Vercel تلقائيًا
٥. الوكيل يحدّث اللوحة (current = «متاح») + يسجّل الحدث في events
```

**ما فيه دمج بدون كلمة «ادمجه» من المالكة لهذا التغيير بالذات.** `main` = الموقع الحي.

## ٥. الأوامر بالضبط

**قبل أي شغل (إلزامي):**
```bash
git fetch origin
git switch -c arena/<اسم-المهمة> origin/main   # أو الفرع اللي يفتحه النظام تلقائيًا
git log --oneline -1                            # تأكد أنك على آخر main
```

**بعد الشغل:**
```bash
python3 - <<'PY'   # فحص صيغة الجافاسكربت قبل الرفع
import re
s=open('index.html',encoding='utf-8').read()
open('/tmp/main.js','w').write(re.findall(r'<script(?![^>]*\bsrc=)[^>]*>(.*?)</script>', s, re.S)[3])
PY
node --check /tmp/main.js
git add -A && git commit -m "وصف قصير عربي"
git push origin HEAD
gh pr create --base main --head "$(git branch --show-current)"
```

**بعد «ادمجه»:**
```bash
gh pr merge <رقم-الطلب> --merge
git fetch origin && git log --oneline origin/main -1   # تأكد من الدمج
```
ثم تحقّق من حالة النشر:
```bash
gh api repos/eilandoll2030-ctrl/Eilan-doll/deployments --jq '.[0:2][]|"\(.id):\(.environment)"'
```

## ٦. قائمة فحص قبل البدء (٥ أسئلة)

1. هل المهمة مسجّلة في اللوحة باسمي؟ (جدول `tasks` + `staff.current`)
2. هل فيه وكيل ثاني `current` على نفس المنطقة؟ لو نعم → **أوقف**.
3. هل سحبت آخر `main`؟ (`git fetch && git log origin/main -1`)
4. هل تعديلي في ملف مشترك (`index.html`) يلمس منطقة وكيل ثاني؟ لو نعم → أبلغ في `events`.
5. هل الطلب يحتاج موافقة (نشر / دفع / إعدادات / كلمة سر)؟ لو نعم → `needs` وينتظر المالكة.

---

## ٧. لو صار تعارض (Conflict)

- **علامته:** `git push` مرفوض، أو `gh pr merge` يقول `CONFLICTING`.
- **الحل:**
  ```bash
  git fetch origin
  git rebase origin/main
  ```
  وأصلح التعارض في `index.html` **يدويًا** (لا تختر «خذ نسختي» ولا «خذ نسختهم» — الملف واحد وفيه شغل الاثنين).
- **قاعدة الإصلاح:** احتفظ بشغل الطرفين، وشيل التكرار فقط (نفس الدالة معرّفة مرتين، نفس الزر مرتين).
- **بعد الإصلاح:** `node --check` + فحص سريع في المتصفح + ارفع الفرع من جديد.
- **لو التعارض كبير:** أوقف، واكتب في اللوحة `needs` بطلب قرار من المالكة (أي شغل يُقدَّم).

---

## ٨. ترتيب الدمج (عشان ما يرجع شغل قديم)

- **طلب دمج واحد في المرة.** الثاني ينتظر لين ينشر الأول.
- بعد كل دمج، الوكيل الثاني **يسحب `main` من جديد** قبل ما يفتح طلبه — الفرع القديم لو اندمج بعد الثاني ممكن يرجع كودًا انحذف.
- لا `force-push` على `main` ولا على فرع وكيل ثاني. أبدًا.

---

## ٩. التكامل مع لوحة المكتب

اللوحة هي **المصدر الوحيد** للحالة — تفاصيلها في `team/board-protocol.md`.

| متى | وش تسجّل |
|---|---|
| قبل البدء | `tasks`: مهمة جديدة (status = `شغل`) · `staff.current` = «شغال على …» |
| أثناء الشغل | `events` (type = `تقدم`) عند كل خطوة كبيرة |
| عند طلب الدمج | `tasks.status` = `ينتظر المالكة` |
| بعد الدمج | `tasks.status` = `خلصت` · `staff.current` = «متاح» · `events` (type = `خلص`) |
| لو احتجت قرار | `needs` (نوعه: `نشر` / `قرار` / `إعدادات` …) |

---

## ١٠. ممنوعات مطلقة

1. ❌ الدفع أو النشر أو تغيير الإعدادات بدون «ادمجه» أو موافقة صريحة لكل مرة.
2. ❌ الدفع مباشرة إلى `main` أو `force-push` على أي فرع مشترك.
3. ❌ تعديل منطقة وكيل ثاني بدون إشعار في اللوحة.
4. ❌ حذف أو إعادة كتابة `index.html` كامل — التعديل يكون جراحيًا (patch على مقاطع محددة).
5. ❌ وضع أسرار أو مفاتيح في المستودع (المستودع **عام**).
6. ❌ تشغيل أداتين (Arena + Cloud) على نفس المهمة بالتوازي.
7. ❌ إغلاق طلب دمج أو فرع وكيل ثاني.
